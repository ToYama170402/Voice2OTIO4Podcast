# 1. システム仕様書

## 1.1 システム概要

本システムは、入力されたマルチトラック音声ファイル群に対して音声認識（Whisper）、NLPに基づく字幕単位の最適分割、カット候補の自動判定を行い、DaVinci Resolve向けにクリップが相互リンク（グループ化）された状態のタイムラインデータ（`.otio`）を生成する自動化パイプラインである。

ムダな区間（フィラー・無音・雑音等）を物理的に削るリップルカットは行わず、元の時間軸を完全に保持したまま、字幕の境界線に合わせて音声ファイルを連続スライス配置する。

## 1.2 主な機能・仕様

1. **エンドツーエンド処理:** 音声ファイルの入力からOTIOファイル出力までを一元処理。
2. **NLP字幕分割:** 単語タイムスタンプ（`word_timestamps`）と形態素解析を用いて、適切な表示文字数・時間制限に収まるよう字幕を文節単位で最適分割。
3. **無断短縮なし（全時間保持）:** 音声データはカットせずタイムライン上にすべて配置。ムダな区間には専用目印トラックにフラグクリップ・マーカーを配置。
4. **DaVinci Resolve 自動リンク連携:** OTIOの `metadata.Resolve_OTIO.Link Group ID` を活用し、インポート時点で「目印クリップ」「本番字幕クリップ」「スライス音声クリップ」の3要素が自動で同期・リンクされた状態を再現。

### 実装契約

- 複数入力は1ファイル=1話者/1音声ソースとして扱い、入力順に独立した3層トラックを生成する。1ファイル内の話者分離は行わない。
- 正常区間は字幕・音声をリンクし、カット候補区間だけ目印・字幕・音声の3要素をリンクする。
- 各音声ソースの先頭から末尾までをOTIO上で保持し、字幕間・先頭・末尾のギャップを欠落させない。

## 1.3 採用フォーマット

- **フォーマット:** **OpenTimelineIO (.otio)**
- **選定理由:** JSONベースで拡張性が高く、DaVinci Resolveのネイティブメタデータ構造（`Resolve_OTIO`）を通じて、FCP7 XMLでは不可能な「インポート時点でのクリップ間リンク」がサポートされているため。
